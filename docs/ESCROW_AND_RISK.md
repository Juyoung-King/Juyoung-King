# 에스크로 설계 & 리스크 대응 상세

플랫폼의 존재 이유가 "거래의 안전성 확보"이므로, 에스크로와 신용 시스템이 곧 제품의 핵심이다.

---

## 1. 에스크로 분할지급 구조 (먹튀 방지의 핵심)

**원칙: 돈은 "일이 실제로 진행된 만큼만" 바이어에게 넘어간다.**

```
현지 구매자 입금 (100%)
   → 플랫폼 에스크로 계좌 보관
      │
      ├─ [1차 지급 ~40%] 차량 매입 증빙 제출 시
      │     · 매매계약서 + 이전등록증(말소증) + 차대번호 실차 사진
      │     · 플랫폼이 차대번호로 서류-실차 대조 검증
      │
      ├─ [2차 지급 ~40%] 선적 증빙 제출 시
      │     · 수출신고필증 + B/L(선하증권) 사본
      │     · 포워더 API/제휴 통해 선적 사실 교차 검증
      │
      └─ [잔금 ~20%] 현지 도착·인도 확인 시
            · 현지 파트너/구매자 인수 확인
            · 분쟁 없을 경우 자동 지급 (도착 후 N일 경과 시)
```

- 비율은 운영하며 조정. 핵심은 **바이어가 돈만 받고 사라질 수 있는 구간을 없애는 것**.
- 바이어 입장에서도 장점: 매입 자금이 부족한 신규 바이어가 1차 지급으로 차량을 매입할 수 있음 → 진입장벽 완화 (단, 1차 지급은 신용등급에 따라 차등: 신규 바이어는 매입 후 지급, 우수 바이어는 선지급).

## 2. 바이어 신용 시스템

| 장치 | 내용 |
|------|------|
| **KYC/KYB** | 사업자등록, 신분증, 계좌 실명 확인, (수출업 등록 여부) |
| **보증금** | 신용등급별 거래 한도 = f(보증금, 누적 이행 실적). 신규는 소액 거래부터 |
| **신용등급** | 이행률(출고일 준수), 분쟁률, 거래량, 리뷰로 산출 — 등급이 곧 거래 한도·선지급 조건 |
| **이행보증보험** | SGI서울보증 등과 제휴하여 고액 거래 커버 검토 |
| **블랙리스트** | 사기·미이행 바이어 영구 퇴출 + 법적 조치. "플랫폼에서 쫓겨나면 재기 불가" 구조가 곧 억지력 |

## 3. 결제·송금 리스크

### 3.1 러시아 (최대 난제)
- 현행 관행(테더/USDT 수령)은 자금세탁·외국환거래법 위반 리스크가 크고, 엑싯 시 실사(due diligence)에서 치명적 → **플랫폼은 처음부터 합법 경로만 사용**
- 대러 제재 준수 필수: 수출 금지 품목·가액 기준(중고차 포함 여부)을 거래 시점 기준으로 상시 확인. 위반 차량은 견적 단계에서 시스템이 차단
- 실무 경로 (법률 자문으로 확정할 것):
  - CIS 제3국(카자흐스탄·키르기스스탄·UAE 등) 법인 경유 정산 — 실제 물류 흐름과 일치하는 구조여야 함 (우회수출 제재 리스크 주의)
  - 현지 결제 수취 법인 설립/인수 → Phase 3의 "현지 법인 인수"와 연결
- **원칙: 제재 우회가 아니라 제재 준수 범위 내 시장(허용 가액 이하 차량, 비제재 품목)에 집중.** 이것이 지속 가능하고 매각 가능한 유일한 구조다.

### 3.2 중동 (UAE 등)
- 상대적으로 결제 인프라 양호 (은행 송금, 현지 PG). UAE는 중고차 재수출 허브(리비아·아프리카향)로 초기 진입 시장으로 적합
- 현지 법인 통한 AED 수취 → 정식 외환 송금

### 3.3 국내 규제
- 에스크로(결제대금예치업)·전자지급결제대행(PG) 등록 요건 검토 — 전자금융거래법
- 외국환 수취 구조 — 외국환거래법 신고 의무
- 초기(Phase 0~1)에는 등록 에스크로 사업자/PG 제휴로 시작, 거래량 확보 후 자체 라이선스 취득

### 3.4 이상거래 대응
- 보이스피싱 등 범죄자금 유입 방지: 입금자-구매자 명의 대조, 이상거래탐지(FDS), 지연 인출 정책
- 계좌 지급정지 리스크 대비: 거래별 가상계좌 분리 운영

## 4. 운영 리스크

| 리스크 | 대응 |
|--------|------|
| 운항 지연·선복 부족 | 복수 포워더 제휴, 출고일-선적일 버퍼 자동 반영 |
| 통관·세무 분쟁 | 관세사 상시 자문, 국가별 통관 요건 DB화 (연식 제한, 좌핸들/우핸들, 배출가스 규제 등) |
| 차량 상태 분쟁 (사진과 실물 상이) | 표준 검수 리포트(성능기록부 + 플랫폼 검수 사진 세트) 의무화, 분쟁 시 에스크로 잔금에서 정산 |
| 환율 변동 | 견적 유효기간 명시, 환헤지 or 원화/USD 고정 견적 정책 |

## 5. 왜 이 구조가 해자(moat)가 되는가

1. **신용 데이터는 복제 불가** — 바이어별 이행률·분쟁 이력은 시간과 거래량으로만 쌓인다. 후발주자가 따라올 수 없는 자산이자 엑싯 시 핵심 밸류에이션 근거.
2. **에스크로 라이선스 + 합법 정산 경로** — 규제를 정면으로 풀어낸 플레이어는 인수자(대기업, PE)가 가장 비싸게 사는 자산.
3. **양면 네트워크 효과** — 바이어가 많을수록 견적 경쟁↑ → 구매자 유입↑ → 바이어 유입↑.
